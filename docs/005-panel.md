# 005 面板

面板是给操作者看的：`superops run` 起来之后，它和管理 API 在同一个地址（默认 `http://127.0.0.1:8797/`，`superops panel` 打开）。它先列需要人处理的工作，再列系统健康，最后才是历史。这篇建立在 [000 理念](000-philosophy.md) 到 [004 提示词](004-prompts.md) 之上。

面板是一个单页（`superops/panel/index.html`），每 5 秒读一次管理 API；它显示的每一样东西都来自 `superops/app/views.py` 的只读视图，每一个按钮都是 `superops/app/http.py` 里的一个动作。所以命令行能做同样的事，这篇把两边并排列出来。

日常批卡片不需要开面板：钉钉群里回一行就够了。面板用来回答群里答不了的问题。

## 三个问题

打开面板，按这个顺序回答三个问题：

1. 现在有没有事要我处理？
2. 系统健康吗，做的事对吗？
3. 某一件工作从触发到评估到工单，来龙去脉是什么？

## 标签页

标签页跟着工作的流向排：**总览**、**来源**、**触发**、**评估**、**执行**、**设置**，另外有一页**业务**。页头有搜索框和术语表（`?`）。

### 读单条记录

- **工单行**在各页长得一样：编号、标题、阶段、规则或“明确请求”、最近的报告或在等的问题。等回答的工单直接带着选项按钮。
- **触发的去向**是一句话：被哪个来源以什么原因过滤、哪个决定及原因、送达了哪张工单、还在排队。带批准凭据的事件会标出是谁在哪张工单上批的。
- **“本来会接单”**是 `observe` 模式留下的记录：这些事件命中了规则，切到 `auto` 就会开工单。评估页有专门的筛选。
- **丢弃的消息**在来源页，带原因：会话收不到了、这个来源没有会话可回。执行器撤回的问题不算丢弃。
- **已结束的工单**显示结果：已完成、已合并、已关闭、无需处理、被人停止，以及它之后还会不会被人的消息恢复。

### 搜索

搜索框按工单编号（`T12`）、工单 id 或其前缀、工单里的文字、触发的 id 或正文、线程键查找，结果分工单、线程、触发三组。

## 命令行独有的

面板没有、命令行有的：`superops ask`（对 Agent 提一个请求）、`superops fire <cron.类型>`（手动补发一条定时触发）、`superops emit`（发一条业务事件）、`superops note` / `superops demand` / `superops published`、`superops inbox`（本机收件箱）、`superops digest`（留底摘要）、`superops agents usage`（登记周用量）。

## 管理 API

面板和命令行用同一组接口。给脚本用的 `/v1/*` 在 007 讲。

| 请求 | 回答 |
| --- | --- |
| `GET /api/overview` | 总览页的全部数据 |
| `GET /api/tickets?filter=person\|open\|queued\|working\|idle\|ended\|all` | 工单行 |
| `GET /api/tickets/<T12 或 id>` | 一张工单的整页 |
| `POST /api/tickets/<T12>/answer` `{"choice", "reason"?, "by"?}` | 回答问题 |
| `POST /api/tickets/<T12>/reply` `{"text"}` | 对工单说一句话：落在它自己的线程上，由它的执行器决定 |
| `POST /api/tickets/<T12>/stop` `{"reason"?}`、`/retry`、`/status`、`/note` `{"text"}` | 停止、重试、请执行器报告状态、给执行器一条备注 |
| `GET /api/threads?filter=recent\|subscribed\|evaluating\|all`、`GET /api/thread?key=` | 线程列表、一个线程的整页 |
| `GET /api/triggers?source=&human=&limit=`、`POST /api/triggers/<id>/reevaluate` | 触发流水（`human=1` 只要人发的，`human=0` 只要定时和流水线的）、重新评估 |
| `GET /api/decisions?kind=`、`POST /api/decisions/<id>/dismiss` | 决定列表、不再提示 |
| `POST /api/thread/unsubscribe` `{"key"}` | 取消一个线程上的全部订阅 |
| `GET /api/sources`、`GET /api/messages?status=` | 来源状态、发件箱里的消息 |
| `GET /api/settings`、`POST /api/mode` `{"mode"}`、`POST /api/pause` `{"paused", "key"?}`、`POST /api/reload` | 设置页；切模式、暂停 / 恢复、重新加载 |
| `POST /api/agents` `{"agent", "action": "reset"\|"usage"\|"open"}` | Agent 的熔断状态 |
| `POST /api/ask` `{"text", "thread"?}`、`POST /api/fire` `{"type"}` | 提请求、补发定时 |
| `GET /api/search?q=`、`GET /api/business?days=`、`GET /api/health/all` | 搜索、业务统计、健康板 |
| `GET /api/autoreply`、`POST /api/autoreply` `{"mode": "auto"\|"off"}` | 钉钉自动回复：开关状态、过滤群和最近 30 条记录；切换开关（见 006 的“钉钉自动回复”） |
| `POST /api/autoreply/exclude` `{"action": "add"\|"remove", "group": "<群ID或群名>"}` | 增删过滤群：群 ID 优先，填群名会去查对应的群 ID |
| `GET /api/publish` | 发布中心和账号页：每个号一行（`key` 账号键、`platform`、`default`、`main`、`accounts` 这个平台几个号；登录状态、发布模式、字数限制、官方发布页）、浏览器操作记录、还没发完的发布包（预览用的标题、正文、话题、封面、素材清单、截图）和最近发出去的 20 个 |
| `GET /api/publish/pack?id=`、`GET /api/publish/media?pack=&name=`（`&shot=1` 取截图，`&download=1` 下载） | 一个发布包的详情；发布包目录里的封面、视频（只给目录里的媒体文件，不接受子路径） |
| `POST /api/publish/packs` `{"action": "approve", "ids": [...], "confirm": true}` | 批准发布：等于在群里批了发布卡片，发出带人工批准凭据的 `content.publish.approved`，按各平台的发布模式执行；只批待批准 / 卡片已发出 / 失败的 |
| `POST /api/publish/packs` `{"action": "record", "id", "url"?}`、`{"action": "try"\|"retry", "id"}` | 人在平台上发完后登记（同 `superops published`）；预演（只试运行）、重试（转了人工的，用原批准再发，同 `superops publish try / retry`） |
| `POST /api/publish/packs` `{"action": "account", "id", "account"}` | 改这个发布包发到哪个号：`account` 是这个平台的账号键，空着 = 用默认账号；已发布、已存草稿、不发的不能改 |
| `POST /api/publish/accounts` `{"action": "qrlogin"\|"check"\|"login"\|"open"\|"code"\|"cancel"\|"logout"\|"rename"\|"default", "key", "code"?, "name"?}` / `{"action": "add", "platform"}` | 对象是账号键 `key`（主号就是平台名，后加的号如 `douyin@2`；老的 `platform` 字段也认）。`add` 给平台再加一个号并直接开始扫码（返回新的 `key`；上次加了没登上的号先复用）；`default` 设为这个平台的默认账号（只能设登录着的号）。网页扫码登录（无界面打开登录页，同 `superops publish qrlogin`）、校验账号并读昵称头像粉丝数（同 `superops publish check`）、在这台 Mac 上开 Chrome 登录、打开草稿箱；`code` 把短信验证码交给正在扫码的登录进程（只在要验证码时收，4–8 位数字）；`cancel` 关掉扫码弹窗、停掉登录进程；退出登录（登录目录挪到 `browser-profiles/.removed/`，清掉这个号的头像和扫码状态；后加的号退出就是移除，是默认账号的话默认改回主号）；备注名 |
| `GET /api/publish/login?key=`、`GET /api/publish/image?key=&kind=qr\|avatar` | 扫码登录的实时状态（`state`、`message`、二维码时间戳 `qr_ts`、`running`；登录进程不在了还停在中途的判成出错）；当前二维码（只在等扫码时给）和账号头像（存在本地，面板不加载外网图片） |
| `GET /api/preflight`（`?refresh=1` 重查） | 启动检查的结果：要提前登录的、要提前放好的密钥里哪些没准备好（见 006）；没准备好的也列在总览的系统问题里 |

失败各有一个状态码：对象不存在 404；被规则拒绝 400，带错误码（如 `notApprover`、`reasonRequired`）；跨站的写请求 403；内部错误 500。配了令牌而请求来自别的机器又没带令牌是 401；本机来的请求不需要令牌。能访问这个地址的人就有操作者的权限（回答问题、停止、切模式），所以默认只监听 `127.0.0.1`。唯一的例外是发事件：不带宿主令牌发来的、需要人批准的事件类型一律被过滤，操作者也不例外。人批红只有三个入口：回答工单上的问题卡片；面板发布中心的“批准发布”（要在确认框里确认，自动发布模式下还要输入“发布”两个字）；面板需求页的“批准开发”（要在确认框里确认）。后两个后端都要求 `confirm: true`。

## 原则

1. **只放要紧的。** 每个元素都在回答三个问题之一，否则删掉。一个数字只有在它会改变操作者的做法时才出现。
2. **定义要精确。** 分类有可检查的定义，互斥且覆盖所有情况，工单阶段就是这样。标签说的是这一行在等谁、需要什么，不是内部状态码。
3. **一个概念一个地方。** 来源的状态在来源页；线程和触发在触发页；决定在评估页；工单在执行页。总览只汇总并链接过去，不变成另一个详情页。
4. **用领域的词。** 面板用 [001](001-domain.md) 的术语。内部标识只出现在折叠的“详情”里；能解析成名字的地方用名字。
5. **状态要诚实。** 一个数等于它链接到的列表的长度；没有哪个状态和另一个事实矛盾。
6. **默认安静。** 健康的状态不占地方。问题必须是可以处理的：偶发的一次网络错误不算。等人的行直接带着它的动作。停止、暂停、切到 `auto` 要确认。
7. **写操作只有人的命令。** 面板能做的都是“人对工单或对宿主下的命令”；它不能替 Agent 做事，也不能改授权依据的文件。
