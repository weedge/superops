# 009 会话

“会话”在 superops 里有三层意思，各管各的：

| 层 | 是什么 | 一句话 |
| --- | --- | --- |
| Agent 会话 | 同一张工单的多轮之间，Agent 能不能接着上一轮的上下文 | 按“工单 × Agent”记会话 ID，下一轮续上；续不上靠提示词里的“这张工单到目前为止” |
| 主 Session | 决定一条候选交给谁的那次模型调用 | 没有长期会话：每个候选一次独立调用 |
| 钉钉会话 | 消息从哪个群 / 单聊进来，回复发到哪去 | 在哪问的回到哪；同一件事的后续靠“线程”串起来，不靠钉钉会话 |

概念的定义在 [001 领域模型](001-domain.md)（工单、派工、轮、线程、订阅），谁的消息算数在 [002 授权](002-authorization.md)，一轮怎么跑在 [003 执行](003-execution.md)，提示词的组成在 [004 提示词](004-prompts.md)，代码在 [007 架构](007-architecture.md)。

## 一、Agent 会话

### 为什么要续接

一张工单往往要跑好几轮：开发工单写 PRD → 人批 → 写代码 → 审查意见回来 → 改；评审工单出卡片 → 人选 → 收尾。每一轮都是一次新的命令行调用。续接让 Agent 带着上一轮的完整记忆往下做：读过哪些文件、为什么这样改、上一轮哪里没做完，都不用重新摸一遍；提示词也不用把角色、团队规则和 Skill 再发一次。

### 会话 ID 存在哪

每一轮结束，适配器从 Agent 的输出里取出会话 ID，宿主按“工单 × Agent”存进状态库（键 `session:<工单 id>`，值形如 `{"claude": "…", "codex": "…"}`）。三个 Agent 都会返回 ID：Claude 是输出 JSON 的 `session_id`，Codex 是事件流里 `thread.started` 的 `thread_id`，Antigravity 是 `conversation_id`。

会话本身由各家命令行保存在自己的目录里（Claude 在 `~/.claude/projects/<工作目录>/`，Codex 在 `~/.codex/sessions/`），宿主只记 ID。不同工单的会话互不相干；同一张工单换了 Agent，各自记各自的。

### 谁续接、怎么续

| Agent | 续接 | 命令 |
| --- | --- | --- |
| Claude | 开（`agents.yaml` 的 `resume: true`） | 照常通过包装脚本 `~/claude.sh` 启动，加 `--resume <会话 ID>` |
| Codex | 开（`resume: true`，2026-11-12 起） | 直调本体 `strict_bin`：`codex -a never -s <沙箱> -C <工作目录> [--add-dir …] exec resume <会话 ID> --skip-git-repo-check --json -o … -`，代理从包装脚本 `~/codex.sh` 里读出来由宿主设 |
| Antigravity | 不续接 | 每轮新开；记下的 ID 目前不用 |

**Codex 为什么续接时要绕开包装脚本。** `~/codex.sh` 固定带 `-s danger-full-access`；首轮的 `codex exec -s workspace-write` 能把它盖掉，但 `codex exec resume` 不接受 `-s`，用 `-c sandbox_mode=…` 也盖不过它。2026-11-12 实测：只读档的续接轮照样写出了文件。直调本体、把沙箱放在顶层参数里之后再测：只读档写文件被拦下，会话记忆还在。所以续接轮一定走 `strict_bin`（`agents.yaml` 里配成 Codex 本体的绝对路径），沙箱、工作目录、可写目录都放在 `exec` 之前。

**续接不改变权限。** 每一轮的工具档位都按规则的 `tools` 重新给（只读 / 工作区 / 浏览器 / 开发），不会因为接着上一轮的会话就继承上一轮的权限。

### 续接时提示词变成什么样

满足三条时提示词是精简版：这个 Agent 有这张工单的会话、它开了续接、这不是这次派工的第一轮。

| 段落 | 完整版 | 精简版 |
| --- | --- | --- |
| 你的角色、团队、订阅与回复、怎么工作、需要人决定时 | 有 | 没有（第一轮给过，会话里还在） |
| 这张工单（编号、范围、授权强度、工作目录、规则） | 有 | 有 |
| 起点 | 有 | 只在派工的第一轮 |
| Skill 正文、Skill 的结构化字段、相关决定 | 有 | 没有 |
| 上下文文件 | 有 | 有 |
| 这张工单到目前为止 | 第二轮起有 | 第二轮起有 |
| 本轮注意、本轮输入、输出 | 有 | 有 |

“这张工单到目前为止”是兜底：最近 6 轮的报告摘要和人作过的决定。会话续不上、或者换了 Agent 时，新接手的 Agent 靠它知道之前发生了什么。每轮的完整提示词留在工单目录的 `turn-<序号>-<Agent>.md`，可以对照看这一轮是完整版还是精简版。

### 特殊情况

| 情况 | 怎么处理 |
| --- | --- |
| 降级换了 Agent（主力熔断、或忙得排队太久） | 接手的 Agent 有它自己这张工单的会话就续它自己的，没有就新开；提示词给完整版，并注明“你是降级接手的 Agent” |
| Codex 续不上（会话文件没了、ID 不认） | 适配器自动新开一个会话再跑一次，提示词里的“到目前为止”兜底 |
| Claude 续不上 | 这一轮按错误处理：按错误类型熔断或换降级链上的下一个 Agent |
| 宿主重启时这一轮还在跑 | 会话 ID 在状态库里，不丢；这一轮带一条“宿主在这张工单执行期间重启过，先检查已产出的文件和外部状态，不要重复已经完成的对外操作”重新开始 |
| 已结束的工单被人的消息唤醒 | 开一次新的派工，第一轮给完整提示词，同时续接原来的会话；机器的事件不唤醒已结束的工单 |
| 这一轮跑的时候又来了新输入 | 一张工单同一时间只跑一轮，新输入等着；这一轮报 `ready` 时还有没处理的输入，不结束，再跑一轮处理它们 |

## 二、主 Session

新来的候选（名单内的人的明确请求，或要按语义判断的事件）交给主 Session 决定：接单开新工单、转给已有工单、停掉工单，还是忽略。主 Session **没有长期会话**：每个候选是一次独立的模型调用，只看这个候选、进行中的工单和规则，看完就结束。这样一条消息的判断不会被前面无关的对话带偏，也没有越聊越长的上下文。每次研判的提示词和输出留在 `~/popto-superops-data/work/_router/<日期>/<评估 id>/`。

命中规则的事件（定时、流水线事件）由宿主直接分派，不调模型。同一线程上已经有一张进行中的工单在处理同一条规则时，宿主把事件直接交给那张工单。

## 三、钉钉会话

| 场景 | 规则 |
| --- | --- |
| 进 | 只监听配置的运营群（`sources.dingtalk.chats`），只认名单里的人；名单外的人和机器人的消息只当数据 |
| 确认、回答 | 发到那条消息所在的会话：在哪个群问的，回到哪个群 |
| 问题卡片 | 发到引出问题的那条消息所在的会话；没有就发到工单开始的会话 |
| 结果 | 发到工单开始的会话；定时和流水线开的工单没有起始会话，发到 home 渠道（运营群） |
| 时间 | 22:30–08:00 静默时段只发 P0，其余早上补发；问题卡片每天最多 10 张 |
| 飞书 | 和钉钉二选一；规则和钉钉一样：在哪问的回到哪。飞书以本人身份收发，没有推送事件，靠轮询（群 15 秒、单聊和 @你 30 秒） |
| 单聊和 @你 | 另有两条监听，只给钉钉自动回复用（飞书靠轮询）：只读的 Claude 每次单独起草（不续接会话），以你的身份回到原会话；要你本人拿主意的转告到运营群。它们不开工单 |

## 四、会话和线程不是一回事

同一件事的后续不靠钉钉会话、也不靠 Agent 会话串起来，靠**线程**：一个业务对象一个线程，例如一条内容 `content:<id>`、一个需求 `demand:<id>`、一个 MR `mr:<项目>!<编号>`、一个定时 `schedule:cron.daily_brief`。工单订阅线程，线程上后来的消息和事件自动送到订阅它的工单，不用再 @ 一次。

| | 线程 | Agent 会话 | 钉钉会话 |
| --- | --- | --- | --- |
| 管什么 | 哪些事件和消息属于同一件事、该送到哪张工单 | 同一张工单的多轮之间 Agent 记得什么 | 消息从哪来、回到哪 |
| 谁持有 | 宿主（状态库） | 各家命令行（宿主只记 ID） | 钉钉 |
| 跨工单 | 一个线程可以被多张工单订阅 | 不跨：一张工单 × 一个 Agent 一个会话 | 一个群里有很多张工单的消息 |

## 五、排查

- **这一轮续上了没有**：看工单目录的 `turn-<序号>-<Agent>.md`，精简版没有“你的角色”一节。续接轮的命令行里有 `--resume`（Claude）或 `exec resume`（Codex）；`turn-*.stderr` 第一行记着命令的开头几段，Codex 带了可写目录时可能截在 `exec` 之前。Codex 续不上新开的那次另记在 `turn-*-fresh.*`。
- **会话 ID 是哪个**：管理接口 `GET /api/tickets/T12` 返回的 `runs` 里每一轮都记了 Agent 和会话 ID（面板上不显示）；状态库的 `session:<工单 id>` 是最新的。
- **想让某张工单从头来**：停掉它重开，或在状态库里删掉 `session:<工单 id>`，下一轮就新开会话、给完整提示词。
- **想关掉某个 Agent 的续接**：`agents.yaml` 里把它的 `resume` 改成 `false`，重启宿主。
