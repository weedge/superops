# 010 使用示例

系统跑起来以后，日常怎么用。按场景排，每个场景给出**在群里怎么说**、**在面板上点哪里**、**在终端敲什么**（三种做法效果一样，挑顺手的），以及之后会看到什么。

- “群”指运营群：飞书或钉钉二选一，现在用的是哪个看面板“设置”页；两边的说法完全一样。机器人名以 `agents.yaml` 的 `notifier.bot_name` 为准，下文写作 `@兔管家`。
- 面板在 `http://127.0.0.1:8797`（`superops panel` 打开）。终端命令在仓库目录下用 `uv run superops …`，下文省略 `uv run`。
- 示例里的工单编号（T12）、发布包（pk_…）、需求（dm_…）、作品 ID 都是示意，换成你看到的。
- 概念的定义在 [001 领域模型](001-domain.md)，授权规则在 [002 授权](002-authorization.md)，面板每一页的说明在 [005 面板](005-panel.md)，配置和排障在 [006 部署与运维](006-deployment.md)。

## 一、开机和每天看一眼

**确认系统在跑、有没有缺东西**

```bash
superops status              # 等你处理的工单、系统问题、过去 24 小时的流量、执行位、不可用的 Agent
superops preflight           # 上次启动检查的结果：哪些登录态 / 密钥没准备好、影响哪些规则、怎么补
superops preflight --refresh # 补完之后复查
superops doctor              # 本机依赖：Agent CLI、dws / lark-cli、ffmpeg、钥匙串、策略、宿主是否在跑
```

面板“总览”是同样的内容：顶部是接单模式、暂停数、在岗 Agent，下面是待办（要你回答的问题）、系统问题和公司日志。

**重启宿主**（改了 `agents.yaml` / 发布模式 / 来源开关之后，或者看着卡住了）：先看总览里“执行中”是不是 0，再

```bash
launchctl kickstart -k gui/$(id -u)/cn.popto.superops
```

正在跑的一轮会带着“先检查已经做了什么”的说明重来，等待的输入和没发出的消息都在库里，不会丢。只是想让它安静一会，用暂停（见第二节），不用重启。

**一天的节奏**（不用你做什么，只是知道什么时候会来什么）：08:00 夜里攒的消息 → 08:30 日报 → 14:00 起今日线索卡片 → 17:00 今晚待发布卡片 → 白天零星的问题卡片（每天最多 10 张）→ 22:30 以后只有 P0。完整的表在 docs/整体流程.md 的“你一天会看到什么”（面板“设计”页能直接看）。

## 二、接单模式和暂停

**刚装好、想先看看它会做什么**：保持 `observe`，定时和业务事件照常评估，但只记“本来会接单”。

```bash
superops mode observe
superops decisions --kind would_accept    # 本来会接哪些、为什么
superops mode auto                        # 看着没问题再放开
```

面板“设置”页也能切模式。三种模式下，名单内的人的明确请求和人在卡片上批准的动作都照常执行；模式只管“没人要求的主动工作”。

**临时停一条规则 / 一个 Agent / 全部**

| 群里 | 终端 | 效果 |
| --- | --- | --- |
| `暂停 collect-metrics` | `superops pause collect-metrics` | 这条规则不再开新工单 |
| `暂停 agent:claude` | `superops pause agent:claude` | 降级链跳过 Claude |
| — | `superops pause origin:panel` | 某个事件来源发来的事件先不处理 |
| `暂停 全部` | `superops pause --reason "周末不跑"` | 全部处理停下（来源照常收、照常留底） |
| `恢复 collect-metrics` / `恢复 全部` | `superops resume collect-metrics` / `superops resume` | 恢复 |

规则 id 在 `policy.yaml`，面板“设置”页列着全部规则，每条旁边有暂停 / 恢复。

**改了配置**：`policy.yaml`、`schedules.yaml`、名单类的 `local.yaml` 改动用 `superops reload`（或面板“设置 → 重新加载策略”）；改之前可以 `superops check` 先校验。`agents.yaml`、发布模式、来源开关要重启宿主。

## 三、让 Agent 做一件事

规则之外的事，直接说。说的人要在名单里（`policy.sources.<飞书或钉钉>.allowed`），名单外的人说了只留底、不开工也不回话。

**群里**

```text
@兔管家 帮我看看昨天那条抖音为什么掉量
@兔管家 把周三那条脚本的开头改成提问式
@兔管家 查一下这周小红书评论里提到“积分”的有几条，都在说什么
```

**终端**（没配群时，确认和结果落在本机收件箱）

```bash
superops ask "帮我看看昨天那条抖音为什么掉量"
superops inbox                      # 看确认和结果
```

会看到：半分钟内一句确认（“收到，T156 在做”），做完一句结果。主 Session 会判断这句话该新开一张工单、交给已经在做这件事的工单，还是不用做。

**跟进、停止、重来**

```text
T156 只看抖音就行，不用管小红书          ← 群里：带编号的话只到这张工单
```

```bash
superops reply T156 "只看抖音就行"
superops stop T156 "不用查了"
superops retry T156                 # 失败的工单修好原因后重跑这一轮
superops ticket T156                # 授权、每条输入、每次派工和报告、每次拉起 Agent 的记录、发出的消息
superops tickets --filter person    # 等你处理的工单；open / working / idle / ended / all
```

面板“执行”页能做同样的事：选工单 → 回复 / 重试 / 停止。

**想看这句话在系统里走了哪几站**：面板总览的“一条指令的旅程”。点你刚说的那条，按“你发出 → 来源收下 → 研判 → 开工单 → Agent 执行 → 报告 → 发件箱 → 回到你”逐站显示：每站的真实数据（研判的原因、哪个 Agent 跑了几秒花了多少、发回的是确认还是结果）、离发出过了多久、落在状态库哪张表。还在进行的那站会高亮，默认跟着最新一条走。

## 四、回答问题卡片（批红）

Agent 需要你拍板时发一张带编号的卡片：标题、建议、理由、风险、明细、选项。回一行就行。

```text
T42 1              选第 1 个选项
T42 approve_all    按选项的 key 选
T42 2 这周人手不够  选第 2 个，写上原因（要求写原因的选项会记进 not-doing.md 或 decisions.md）
T42 1 3,5          选项的动作和明细一一对应时，只批明细里的第 3、5 条
T42 标题再短一点    后面不是选项：当成一条跟进消息交给这张工单
```

终端：`superops answer T42 1`、`superops answer T42 2 这周人手不够`、`superops answer T42 1 3,5`。面板：总览的待办里直接点选项，或点“只批部分”勾明细。

会看到：一条回执——选了什么、发出了几个已批准的动作。批准的动作不看接单模式，`observe` 下也执行。卡片到期没人回（默认 24 小时），按卡片上写好的安全选项处理，这个选项永远不做对外动作（不发布、不发评论、不合并）。

## 五、记决定和不做的事

```text
记下来：视频号的标题一律不超过 16 个字
```

```bash
superops note "视频号的标题一律不超过 16 个字"
```

追加到 `decisions.md`。以后每轮提示词的“相关决定”会按关键词带上它，Agent 定过的事直接照办，不再问你。卡片上选了“不做”并写了原因的，会进 `not-doing.md`，同类的事下次不会再提。

## 六、内容：选题 → 写稿 → 复核 → 出图

**每天 09:30 今日发布推荐**：今天还没有能发的内容时，从写好稿的图文里挑，发一张“今天发哪篇图文”卡片（今天已有发布包在走就不出声）。也可以随时问 `@兔管家 今天发什么`。

```text
T300 1         发推荐的第一篇：自动出图（按稿子逐页排版，用帮助文档截图，3:4 竖版）→ 图文质检 → 发布包 → 进 17:00 待发布卡片
T300 3         今天不发
```

出图大约 30–60 分钟；赶不上 17:00 的，发布包入库时会当场补发一张待发布卡片。批准发布后小红书图文和视频一样按发布模式执行：现在是“存草稿”——8 张图、标题、正文、话题、AI 声明都自动填好存进本机专用 Chrome 的草稿箱（`superops publish open xiaohongshu` 或发布卡上“打开草稿箱”），你检查后点发布，发完回填链接。抖音、视频号的图文还没有自动发布器，走人工。现在就想推一次：`superops fire cron.daily_publish_plan`。

**在日历上直接排**：业务 → 内容 → 内容日历。把卡片拖到另一天就改了计划日（手机上用卡片上的“改日期”）；鼠标移到卡片上点“发布”，效果和在推荐卡片上批准一样（出图 → 质检 → 发布包 → 待发布卡片，计划日已过就今天发）；“删除”把不要的选题从日历上去掉（已经在发布或已发的删不了）。

**每周五 15:00 自动排下周选题**，发一张选题卡片。想现在就排：

- 面板：业务 → 内容 → 内容日历 → **立即排选题…**（可选“下一个自然周”或“从明天起 7 天”，还能写一句这次的方向，例如“多排小红书图文，重点讲批量口播”）；
- 终端：`superops fire cron.topic_planning`。

**批选题**

```text
T60 1          全部按建议排
T60 1 2,4,6    只批第 2、4、6 条
T60 3 下周主推上新，先不做行业模板
```

批了的每条选题开一张写稿工单（Claude）。写完自动送合规复核（Codex，审查者不会是写稿的 Agent），打回就在原稿上改，最多 3 轮。中间过程不出现在群里，结束时 home 渠道有一条结果。

**想改稿**：`T61 开头换成一个问题，结尾加一句引导评论`，写稿的工单接着上一轮的会话改。

**看进度**：面板“业务 → 内容 → 内容日历”按自然周排着所有选题，格子里是支柱颜色、状态和各平台发布包的小圆点（实心是已发布）。

## 七、发布

**17:00 的“今晚待发布”卡片**

```text
T70 1          全部发布（三个平台都是存草稿模式时，这个选项叫“全部存草稿”）
T70 1 1,3      只批第 1、3 条
T70 2 今晚不发  都不发，要写原因（到期也按这个处理）
```

**在面板上批**：业务 → 内容 → 发布中心。待发布的包按内容分组，每个平台一张预览卡（封面、标题 / 正文 / 话题带字数上限，超了标红）。勾选 → **批准发布所选…** → 确认框写明每个平台会发生什么；有平台是“自动发布”模式时要输入“发布”两个字才放行。

批准后按各平台的**发布模式**执行（在 `local.yaml` 的 `publishers.<平台>.mode`，面板只读；改完重启宿主）：

| 模式 | 会发生什么 | 你要做什么 |
| --- | --- | --- |
| `draft` 存草稿 | 浏览器自动填好，存进平台草稿箱，不点发布 | 去草稿箱检查后自己点发布，再登记（见下） |
| `live` 自动发布 | 自动填好并发布；离计划时间还来得及就用平台的“定时发布” | 什么都不用做，成功了自动登记、自动排采集 |
| `dry_run` 试运行 | 填好停在发布按钮前截图 | 看截图 |
| `off` 人工发 | 把文案和素材推给你 | 自己发，再登记 |

**草稿在哪**：视频号在视频号助手的草稿箱；小红书、抖音网页版的草稿只存在本机专用 Chrome 里——

```bash
superops publish open xiaohongshu     # 或 douyin；面板“账号”页 / 发布卡上也有“打开草稿箱”
```

**自己发完以后登记**（登记后自动排 1 小时 / 24 小时 / 3 天 / 7 天的数据采集）

```text
已发 pk_c_20261113_01_douyin https://www.douyin.com/video/…
已发 pk_c_20261113_01_wechat_channels          ← 视频号没有链接就只回编号
```

```bash
superops published pk_c_20261113_01_douyin https://www.douyin.com/video/…
```

面板：发布卡上 **已发布，回填链接…**。

**人工路径**（不想用浏览器自动化，或自动的转了人工）：发布卡上先勾“我已核对当前版本”，然后复制标题 / 正文 / 全文、下载封面和视频、打开官方发布页，自己发完回填链接。内容改过的话要重新勾。

**自动发布转了人工**

| 群里的提示 | 怎么办 |
| --- | --- |
| 要身份验证（抖音短信、小红书扫码） | `superops publish retry <发布包ID> --headed`，在弹出的窗口里验证，接着用原批准发（批准 24 小时内有效）；面板发布卡上“重试发布…” |
| 登录失效 | `superops publish login <平台>` 重新扫码，再重试 |
| 抖音“只能暂存一条” | `superops publish open douyin` 把上一条发掉或放弃，再重试 |

**发之前想先看看会填成什么样**：发布卡上“预演”，或 `superops publish try <发布包ID>`（只试运行，不发）。

**账号**：面板“业务 → 内容 → 账号”每个平台一张卡，显示头像、昵称、账号 ID、粉丝数和登录状态。分两组：抖音、小红书、视频号能自动发布；快手、B站、知乎、公众号先只管账号（登录、校验、看身份），发内容走人工路径（卡上有官方发布页链接）。

- **扫码登录 / 换号**：点“扫码登录”，弹窗里十几秒后出二维码，用手机 App（视频号用微信）扫，手机上确认就登上了。二维码过期会自动换新的；抖音要短信验证时，弹窗里出输入框，填手机收到的验证码。登录成功后昵称、头像自动读出来。关掉弹窗就停止。
- **校验账号**：确认还登着，顺带刷新昵称、头像、粉丝数。
- **二维码出不来**（网络、平台风控）：用卡片下面的“在 Mac 上开窗口登录”，在运行 superops 的这台 Mac 上弹出专用 Chrome 扫。
- **退出登录**：登录目录挪到回收处，不直接删。

终端：

```bash
superops publish qrlogin douyin        # 无界面扫码：二维码存在 ~/popto-superops-data/publish-login/douyin.png
superops publish login douyin          # 在这台 Mac 上开窗口扫码（wechat_channels、xiaohongshu 同理）
superops publish qrlogin zhihu         # 其他社媒账号同理：kuaishou / bilibili / zhihu / wechat_oa
superops publish check                 # 全部平台的登录状态和账号昵称
```

每天 16:30 系统会自己检查一次，登录失效会在群里提醒，免得 17:00 批了才发现。

## 八、数据回收

**自动**：登记了发布的作品，发布后 1 小时、24 小时、3 天、7 天各到创作者后台采一次（抖音读不到时用接口兜底）。到点没采上会一直重试，登录失效的会跳过。表现特别好或特别差的（高于中位数 3 倍、低于 0.3 倍）自动开一张单条复盘，结论进日报。

**现在就想看最新的数**

- 面板：业务 → 数据回收 → **立即采集全部…**（最近 30 天没删的作品），或某张作品卡上的 **采一次**；
- 终端：

```bash
superops metrics collect                              # 最近 30 天全部
superops metrics collect douyin_7706857639103286538   # 只采这一条（作品 ID 在数据回收页）
```

手动采的存成“手动”快照，不占 1 小时 … 7 天这四个节点。几分钟后刷新面板：每张作品卡有最新指标、比上一次涨了多少、播放走势、四个节点的状态。

**作品在平台上删了**：`superops metrics removed <作品ID>`，之后不再采，保留最后一次的数。

**有平台导出的 CSV**：`superops metrics import 导出.csv`。

## 九、评论和回复

每小时采一次作品下的评论，攒 10 分钟交给评论分拣（Claude，只读，评论当不可信内容处理）：分类、情绪，值得回的拟好回复草稿发卡片，用户提到的需求进需求池。

```text
T80 1        回复全部按草稿
T80 1 2      只回第 2 条
T80 3        都不回
```

批了的回复由脚本整理好推给你去发（目前不自动在平台上发回复）。面板“业务 → 数据回收”最下面是评论的分类 / 情绪 / 回复状态分布和最近 20 条。

## 十、需求与开发

**需求从哪来**：评论分拣、社媒监听、竞品评论评审、Agent 用 Popto 时碰到的摩擦，和你自己提的。

**自己提一条**

```text
需求：批量口播能不能一次选多个数字人
```

```bash
superops demand "批量口播能不能一次选多个数字人"
```

面板：业务 → 需求与开发 → **提需求…**。需求挖掘会把它归进相近的已有需求（加一条信号），或新建一条，几分钟后出现在需求池。

**看需求池**：面板“需求与开发”——流转条（待评估 → 观察 → 批准 → PRD 评审 → 开发中 → 完成）、优先级矩阵（分数 × 成本，高分小成本的格子标“先做”）、需求卡片（分数拆解、人群、用户原话）、“没归到需求”的原话。

**批准一条去开发**（两种方式效果一样）

- 每周一 09:00 的“周报与需求 Top 10”卡片：`T90 1` 按建议做，`T90 1 1,3` 只批第 1、3 条；
- 面板需求卡上 **批准开发…** → 确认。

批准后开一张“需求 → PRD → 开发”工单（Claude，独立 git worktree）：

1. 先写 PRD，发一张 PRD 卡片：`T91 1` 批准，`T91 验收标准再加一条：失败要能重试` 让它改；
2. PRD 批了，在同一张工单里开发、提交，宿主推送并开 MR；
3. Codex 审查（最多 3 轮），打回的意见回到开发工单，同一个分支接着改；
4. 审查通过后过合并闸门（数据库迁移、计费、鉴权、密钥、改动超过 800 行都要人看），发合并卡片：`T95 1` 合并 / `T95 2 先不合`；
5. 合并后核实上线：配了线上版本地址的自动核实，没配的会说一句“请确认上线”。

开发工单在 MR 开出后显示“等你验收”，它在等 MR 被合并或关闭。人手推到 `agent/*` 分支上的修改最晚 30 分钟被发现并送审。

**先不做**：需求卡上 **观察**（等更多信号）或 **搁置…**（写一句原因，进“已搁置”，随时能恢复）。

**测试需求**：原话标了【测试】的需求带着测试标记走完全程，合并卡片建议“先不合”，也不会被自动合并——用来试一遍链路很合适。

## 十一、获客

**每天 14:00**：按“在用”的意图词用接口搜抖音、小红书、视频号、快手近 24 小时的作品；**14:10** 浏览器补位搜知乎、B站、搜狗微信。判断出的线索发一张“今日线索”卡片（最多 10 条，明细里就是要发的评论原文）。

```text
T100 1        跟进并发评论（用品牌号在作品下发卡片上的原文，目前只有抖音，每天最多 10 条）
T100 1 2,5    只发第 2、5 条
T100 2        只记“待跟进”，我自己去互动
T100 3        都不跟进（到期也按这个登记，不会发评论）
```

发完会有一条结果：发出几条、哪些要你自己去发（没确认到的标出来）。

**之后的跟进在面板上记**：业务 → 获客 → 跟进看板，按“卡片待批 / 待跟进 / 已评论 / 已联系 / 已回复”分栏。

| 你做了什么 | 在卡片上点 |
| --- | --- |
| 评论要你自己发（平台不支持自动发、或当天发满了） | “复制评论” → “去原帖 ↗” 发出去 → “我已发评论”（挪到已评论，系统不会再发这条） |
| 私信了 / 加了联系方式 | “已联系” |
| 对方回复了 | “对方回复了”（挪到已回复，转人工深聊） |
| 不想跟了 | “不跟进…”，可以写一句原因；归档里随时“拉回待跟进” |

这些只改记录，不会对外发任何东西。看板上面的漏斗（监听到作品 → 线索 → 上卡片 → 评论 → 已联系 → 已回复）每一步写着转化率，能看出卡在哪一步。

**管意图词**

```bash
superops terms add "保险团队长怎么带新人" --category persona
superops terms disable "数字人口播"
superops terms enable "数字人口播"
superops terms remove "数字人口播"
```

面板“获客”页底部：**添加意图词…**、每个词的停用 / 启用 / ×。条形是近 7 天命中数，命中少的可以停掉。

## 十二、竞品和 GEO

**每周四 10:00 竞品流程**：按竞品词搜讨论最多的作品、拉用户评论，挖出候选需求发评审卡片（每条带来源作品和 Popto 现状）。批了的进需求池：

```text
T130 1          全部进需求池
T130 1 1,4,7    只要这几条
```

满 28 天另出一份竞品调研报告（定位、功能、价格、社媒、和 Popto 的对比，每条附来源），摘要发到群里。现在就想要一份：`superops fire cron.competitor_research`。

**每周三 10:00 GEO 检查**：Popto 在各家 AI 助手答案里的可见度，结论进日报。

## 十三、外部系统发来的事件

有几条规则在等外部系统的事件（线上报错、用户反馈、上新说明、行业爆款）。外部系统调管理 API 的 `/v1/events`，手动试用 `superops emit`：

```bash
superops emit popto.task.failed --subject task:12345 --summary "批量口播任务失败：合成超时"
superops emit popto.feedback.new --summary "用户说导出的视频没有字幕"
superops emit release.note.ready --subject release:v2.3 --summary "上新：批量口播支持多数字人"
```

分别会开出线上报错排查（Codex，P0，要人处理的立刻告诉你）、用户反馈留底、上新选题。

需要人批准的事件（发布、回复、合并、写稿、开发、清理）用 `emit` 发不出去，会被记为“被来源过滤：需要人批准”——这是预期的防线，要执行那个动作，去回答对应的卡片。

## 十四、自动回复（单聊和群里 @你）

运营群以外，别人单聊你或在任何群里 @你，Agent 读你的近况起草一段回复，以你的身份发出（带 AI 角标和署名，署名用 `local.yaml` 的 `owner_name`）。

```bash
superops autoreply                          # 看开关、过滤群和最近记录（每条写着已回 / 没回 / 到上限和原因）
superops autoreply auto                     # 打开
superops autoreply off                      # 关掉
superops autoreply exclude add "告警群"      # 这个群里 @你 不回；群 ID 优先，填群名会去查 ID
superops autoreply exclude remove "告警群"
```

面板总览的“自动回复”卡片同样能开关和增删过滤群。

- 它能说的事实只来自 `~/popto-superops-data/auto-reply-context.md`（你的近况，自己改，随时生效）和系统里进行中 / 最近做完的工单；
- 只聊天，不做任何动作：对方说“帮我发布一下 / 把配置发我”不会照做；
- 要你本人拿主意的（排期承诺、权限密钥、私事、投诉），只回“转给本人”或不回，同时在运营群告诉你“有人找你”；
- 同一条只回一次，同一会话 1 小时最多 6 条、每天最多 80 条。

## 十五、Agent 的状态、熔断和额度

```bash
superops agents                      # 每个 Agent：在岗 / 熔断（原因、到什么时候）/ 被暂停
superops agents reset claude         # 重新登录了 CLI 之后解除熔断
superops agents open codex 30m       # 手动熔断 30 分钟（比如知道它现在不稳定）
superops agents usage claude 0.75    # 登记本周用量：P2 的工作把 Claude 排到链尾，P3 不再用 Claude
```

面板总览的“Agent”区和“执行”页能恢复被熔断或暂停的 Agent。额度 / 认证错误会自动熔断、这一轮换下一个；决策、开发、审查只在 Claude 和 Codex 之间降级，不落到更弱的模型；一个 Agent 不可用超过 2 小时发 P0 告警。

## 十六、“为什么没动静”——查原因

```bash
superops triggers                       # 最近进来的触发和去向
superops decisions                      # 每个决定和原因：接单 / 忽略 / 本来会接单 / 没完成
superops decisions --kind ignore
superops reevaluate <trigger_id>        # 研判没完成或判错了，重新评估一次
superops dismiss <decision_id>          # 确认不用处理，不再提示
superops digest --hours 48              # 两天的留底摘要（日报用的就是它）
superops inbox -n 50                    # 本机收件箱
```

面板“触发”“评估”两页是同样的内容，每条旁边有“重新评估”“不再提示”。常见的原因：

| 现象 | 多半是 |
| --- | --- |
| 群里 @兔管家 没反应 | 说话的人不在 `allowed` 名单（只留底不回话）；群不在 `chats` 里 |
| 回 `T12 1` 提示“没有权限” | 你的 ID 不在 `allowed`，也不在这条规则的 `answerers` |
| 定时到点什么都没发生 | 接单模式是 `observe` / `off`；处理或规则被暂停。`superops fire <cron.类型>` 手动补一次 |
| 批了卡片却没开工单 | 接它的规则被暂停、到了轮数上限或超预算——`superops decisions` 里写着 |
| 工单一直排队 | 执行位满了，或在等前置工单（`after`）；`superops status` 看执行位 |
| 卡片迟迟没发出来 | 静默时段（22:30–08:00 只发 P0）或当天 10 张上限，顺延了 |

更全的排障表在 [006 部署与运维](006-deployment.md) 的“排障”。

## 十七、清理和数据保留

**每周日 10:00 大扫除**：

- 运营：连续零命中的监听意图词、过期没做的选题列成清单发卡片，`T140 1` 按建议清理（停用这些词、把选题标为过期），`T140 2` 先保留；到期按“先保留”处理。
- 代码：本周合入的代码和文档里重复的、补丁式的、停用了没拆干净的，按普通开发任务改、开 MR，走审查和合并卡片，不进这张卡片。

**每天 04:30 数据保留清理**：工单目录、运行目录、发布截图保留 90 天；状态库里的正文 170 天后清空、元数据永久保留；评论原文 180 天删除。想先看看会动什么：

```bash
superops retention --dry-run
```

## 十八、换聊天渠道、改群、改审批人

面板“设置”页：

- **切到另一个聊天渠道**（飞书 ↔ 钉钉，只能用一个）：确认后宿主自动重启，约 15 秒；已经发到另一边、还没回答的卡片，要在新渠道里回；
- **改群**：填群 ID 或群名；
- **增删审批人**：只认 ID，不认昵称。

也可以直接改 `local.yaml` 的 `sources` / `policy.sources`，然后 `superops reload`（来源开关的改动要重启）。

## 十九、改 Agent 的做法（Skill 和规则）

- **改某类工作的做法**：面板“Skill”页打开对应的 Skill（例如 `ops-script-writing` 写稿、`ops-social-listening` 监听），直接编辑保存，下一轮用到它的工单就按新版本做；保存前的版本留在“历史版本”里，可以恢复。
- **改规则**（谁来做、什么时候做、要不要人批）：改 `policy.yaml` 或 `schedules.yaml`，`superops check` 校验后 `superops reload`。加新规则、新来源、新 Skill 的写法见 [008 扩展手册](008-cookbook.md)。
